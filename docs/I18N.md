# Internationalization

## Languages

The project currently supports:

* Italian — `it`
* English — `en`
* German — `de`

Italian is the primary and canonical language of the website.

Translation files:

```text
data/i18n/it.json
data/i18n/en.json
data/i18n/de.json
```

---

## Architecture

Internationalization is handled by the JavaScript module:

```text
js/modules/i18n.js
```

Localized content is stored separately from the main HTML structure in JSON files.

The HTML and JavaScript should use the existing i18n system rather than duplicating the same content for each language.

---

## Language Codes

The supported language codes are:

```text
it
en
de
```

Use these exact codes consistently in:

* translation files
* language switcher
* HTML language attributes
* JavaScript language state
* localized content keys

---

## Default Language

Italian is the default language.

The Italian translation file:

```text
data/i18n/it.json
```

is the canonical source for restaurant content.

English and German translations should preserve the meaning, tone and context of the Italian content.

---

## Translation Rules

Translations must not be treated as literal word-for-word conversions.

Translations should preserve:

* meaning
* tone
* context
* hospitality character
* editorial style
* calls to action
* culinary terminology
* location-specific terminology

Restaurant names, proper names and established brand terminology should not be translated unless there is an established localized form.

---

## Translation Structure

All language files should maintain the same key structure.

Example:

```json
{
  "hero": {
    "title": "...",
    "description": "..."
  },
  "navigation": {
    "home": "...",
    "menu": "...",
    "reservation": "..."
  }
}
```

When a new translation key is added to the Italian source, the corresponding key should be added to the English and German files.

Do not rename existing keys in only one language file.

---

## Missing Translations

A missing translation should not result in broken interface elements.

The existing i18n system should provide an appropriate fallback where supported.

If a translation is missing during development, the missing key should be identified and corrected rather than permanently relying on fallback content.

---

## Content Accuracy

Factual restaurant information must remain consistent across all languages.

This includes:

* address
* telephone
* email
* opening hours
* menu information
* prices
* reservation information
* location information
* events
* restaurant-specific facts

Localized versions must not introduce information that does not exist in the canonical Italian content.

---

## Dynamic Content

Content generated or inserted by JavaScript should use the i18n system where it requires localization.

This includes, where applicable:

* modal content
* navigation labels
* buttons
* interface messages
* reservation interface text
* gallery labels
* dynamic section content

Do not hard-code language-specific UI strings inside JavaScript modules when an existing translation key can be used.

---

## HTML Language

The document language should reflect the currently selected language where supported by the existing implementation.

The default document language is:

```html
<html lang="it">
```

Language-specific values should use the standard language codes:

```text
it
en
de
```

---

## Adding a New Language

Adding another language requires updating all relevant parts of the i18n system.

At minimum:

1. Create a new JSON translation file in `data/i18n/`.
2. Preserve the existing translation key structure.
3. Add the language to the language configuration in `js/modules/i18n.js`.
4. Add the language to the language switcher.
5. Verify all interface elements have translations.
6. Test responsive layouts with the new text lengths.
7. Verify the document language handling.
8. Test language persistence and switching behavior.

Do not add a language by creating only a new JSON file.

---

## Translation Quality

Translations should be reviewed for:

* grammatical correctness
* natural phrasing
* cultural context
* hospitality terminology
* culinary terminology
* consistency of repeated terms
* correct calls to action

The Italian version remains the reference for the intended meaning.

---

## Development Checklist

When modifying localized content:

* update the Italian source first when the content is new
* keep all language files structurally synchronized
* verify all translation keys
* check buttons and navigation labels
* check modal content
* check mobile layouts
* check longer English and German text
* verify restaurant facts
* test language switching

Never remove or rename a translation key without checking all supported languages and the JavaScript code that uses it.
